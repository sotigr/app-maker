# 0004. Layer import rules: published language and pure libraries

Date: 2026-10-31 · Status: accepted

## Context

Section 15.2 says a `domain` package may import only the standard library, `kernel` and its
own `domain`. Other parts of the spec need more than that:

- The Feature aggregate holds a `schema.TypeID` (section 3.1), and the write rules need the
  compiled type, which section 2.3 calls Schema's published language, read through the
  `TypeRegistry` port.
- `View` holds a compiled `*jsonschema.Schema` validator (section 4.5), and compiling
  expressions with expr is a step of the domain compiler (section 4.4).
- `api` packages "may import kernel" only, but `content/api` needs to mention schema type IDs.

## Decision

- `api` packages may import the standard library, `kernel`, and other contexts' `api` packages.
  The `api` import graph must stay acyclic.
- `domain` packages may additionally import any context's `api` package (consuming the
  upstream published language, conformist relationship) and these pure, I/O-free libraries:
  `github.com/expr-lang/expr`, `github.com/santhosh-tekuri/jsonschema/v6`,
  `github.com/cockroachdb/apd/v3`, `github.com/google/uuid`.
- `application`, `infrastructure` and `interfaces` keep the section 15.2 rules, with "other
  contexts' `api`" allowed everywhere it is allowed for `application`.
- The compiled type is published from `internal/schema/api`; the compiler that produces it lives
  in `internal/schema/domain`.

## Consequences

Domain packages still cannot reach drivers, HTTP, `platform`, or other contexts' internals,
so the property the rule protects (pure, independently testable domains) holds.
The rules are encoded in `.golangci.yml` with depguard, generated by `scripts/gen-depguard.sh`.

## Addendum: tests

Test files (`_test.go`) are excluded from the depguard layer rules. Tests act as a small
composition root: domain tests wire the real expression compiler and the jsonschema adapter
instead of fakes, so the compiler is tested against the behavior it has in production.
Production code in the same packages still follows the rules above.

## Addendum: concurrency helpers

Application packages may import `golang.org/x/sync` (errgroup), as section 15.6 prescribes
errgroup for fan-out. Domain packages still start no goroutines.
